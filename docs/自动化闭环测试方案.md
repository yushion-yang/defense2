# 自动化闭环测试方案

## 流程总览

```
脚本1（环境检查/增量更新）
  ↓
脚本2（自动对局 → M1/M2 产出 JSON+截图）
  ↓
脚本3（AI 分析 M1/M2 → 新问题写 M4）
  ↓
M4 为空？ → 是 → 本轮结束 ✓
  ↓ 否
脚本4（修复 M4 问题 → make build → 归档 M3）
  ↓
build 不过？ → 继续修直到通过
  ↓
回到脚本2（回归验证，进入下一轮循环）
```

## 目录结构

```
docs/autotest/
├── last_commit.txt   # 文件A：上次更新自动对局系统时的 git commit hash
├── M1/               # 自动对局产出 — JSON 数据（波次统计、DPS、金币曲线等）
├── M2/               # 自动对局产出 — 截图（关键帧、异常画面等）
├── M3/               # 已处理归档 — 脚本4修复完的 task 文档
└── M4/               # 待修复队列 — 脚本3发现的新问题
```

## 脚本详细说明

### 脚本1 — 环境检查 / 增量更新

- **依赖**: `docs/autotest/last_commit.txt`（文件A）
- **任务**:
  1. 读取 `last_commit.txt` 中的 git commit hash
  2. `git diff <old_hash>..HEAD` 检查自动对局相关代码是否有改动
  3. 如有改动 → 更新自动对局系统逻辑（autoplay 策略、测试参数等）
  4. 更新 `last_commit.txt` 为当前 commit hash
  5. 无改动 → 跳过，直接进入脚本2

### 脚本2 — 自动对局

- **依赖**: 无（直接运行游戏）
- **任务**:
  1. 运行单机自动对局系统
  2. 对局过程中自动产出:
     - JSON 数据 → `docs/autotest/M1/`（波次统计、DPS、金币、泄漏、FPS 等）
     - 截图 → `docs/autotest/M2/`（关键帧、异常画面）
  3. 对局结束后退出

### 脚本3 — AI 分析

- **依赖**: `M1/`、`M2/` 下的 JSON 和截图
- **任务**:
  1. 从 `M1/`、`M2/` 获取本轮产出（数量取决于 Claude 上下文处理能力）
  2. 读取 `M3/`（已处理归档）了解历史修复情况，避免重复报告
  3. 结合项目当前代码状态进行分析
  4. 发现新的 bug 或优化项 → 写入 `M4/`
  5. 未发现新问题 → `M4/` 为空，本轮闭环结束

### 脚本4 — 自动修复

- **依赖**: `M4/` 下的待修复文档
- **任务**:
  1. 从 `M4/` 取出问题（数量按批次控制）
  2. 逐个修复
  3. `make build` 验证编译通过
     - 不通过 → 继续修 build 错误，直到通过
  4. 将已处理的 task 文档从 `M4/` 归档至 `M3/`
  5. 完成后回到脚本2 进行回归验证

## 终止条件

- **正常终止**: 脚本3 分析后 `M4/` 为空（无新问题）
- **防死循环**: 同一问题连续 N 轮修不掉 → 标记跳过，继续处理下一个
- **轮次上限**: 可配置最大循环轮次（如 5 轮），防止无限跑下去
