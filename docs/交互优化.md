交互系统审查报告

一、Bug 级问题（应修复）

1. 吉祥物(Mascot)点击穿透到 Stage 输入 [中等]

game.go 中 mascot 点击用 IsMouseButtonJustPressed，在 scene.Update() 之后运行。Stage 的 gesture 系统已经看到了同一帧的按下事件。吉祥物在右下角，与 warden toggle 按钮、ActionBar                               
区域重叠时，点击吉祥物会同时触发底层 UI 操作。

根因：没有事件消费(consume)机制，两层独立检测同一帧的输入。

2. Settings 场景滑条不支持触摸 [中等]

settings.go 的音量滑条用 IsMouseButtonJustPressed + IsMouseButtonPressed，没有检查 JustPressedTouchIDs。移动端用户无法调节音量。其他按钮（画质/返回）也仅用鼠标 API。

3. Delete/Backspace 键双重触发 [低]

stage_input.go 中，modeTowerSel + testMode + 有 hoveredEnemy 时，同一次按键会先卖塔（line ~218，设 mode=modeIdle），然后又杀敌人（line ~233）。一次按键两个动作。

4. modeUpgrade 中 Escape 处理有死代码 [低]

Lines 111-115 的 early-return 块已处理了 modeUpgrade 的 Esc，但 lines 137-139 的通用 Esc 处理又写了一遍 modeUpgrade 分支，永远不会执行。

8. 非 Stage 场景零键盘快捷键

除 Settings 的 Esc 外，Title/Select/CampaignSelect/TestSelect/Result/WardenSelect 无任何键盘支持：
- 无 Enter/Space 确认开始
- 无方向键导航卡片/列表
- 无数字键快速选难度
- Title 场景无"任意键继续"
- Result 场景无 R 重玩 / M 返回

9. HitTest 架构不统一

存在 3 种不同的 hover/hit 检测模式：
- Pattern A（缓存 rect）：actionBar, topBar, infoPanel — Draw 时缓存 rect，HitTest 读取
- Pattern B（重算 rect）：buildMenu, spawnMenu, itemPanel — HitTest 独立重算几何
- Pattern C（自包含 Update）：choicePanel, wardenSelectOverlay — 内部处理 hover+click

infoPanel 的能力按钮更是在 Draw 回调中读 draw.CursorPos()，将渲染和输入耦合了。

三、可优化点（提升体验）

10. IsOnUI 底部 120px 保护区过大

gesture.go 的 IsOnUI 把 y > 420（屏幕底部 120px）全标记为 UI 区域，阻止拖拽启动。但 ActionBar 实际只占 ~54px。地图下部 66px 区域无法启动相机拖拽，大地图体验受影响。

11. 右键完全未利用

input.Manager（旧系统）支持右键，但 Stage 的 Gesture 系统和所有场景均无右键处理。桌面端可考虑：
- 右键取消选中/退出当前模式
- 右键快速出售塔
- 右键查看敌人详情

12. spawnMenu HitTest 无边界预检

SpawnMenuHitTest 对每次调用都遍历所有卡片，没有像 buildMenu/itemPanel 那样先做面板边界检查提前返回。

13. 返回按钮 hit area 硬编码重复

CampaignSelect/TestSelect/WardenSelect 三个场景的返回按钮 hit test 都用 mx >= 20 && mx <= 90 && my >= 16 && my <= 44 魔法数字，重复 3 次。应抽取为共享常量或 helper。

14. 禁用按钮行为不一致

- itemPanel: HitTest 对 count=0 的卡片返回 -1（HitTest 层阻断）
- actionBar: 道具 count=0 仍返回 "items"（调用方阻断 + 抖动动画）
- infoPanel upgrade: 金币不够仍可点击（仅视觉灰显，调用方检查）
