# Ebitengine 渲染与 HiDPI 问题解析

## 背景知识

### 什么是逻辑分辨率和物理分辨率？

你的 MacBook Retina 屏幕物理像素是 2880×1800，但操作系统告诉应用程序"你的屏幕是 1440×900"。这个 1440×900 就是**逻辑分辨率**，2880×1800 是**物理分辨率**。两者的比值叫 **devicePixelRatio**（设备像素比），Retina 屏是 2.0。

### 浏览器怎么处理的？

JS 版 tower-defense 运行在浏览器里。浏览器的 Canvas 非常聪明：

```
你的代码写：canvas 尺寸 1200×540
浏览器内部：创建 2400×1080 的实际画布（自动 ×2）
你画一条线在 (100, 200)：浏览器在物理像素 (200, 400) 画
你画 16px 文字：浏览器用 32px 光栅化，显示为 16px 大小
```

**你的代码完全不知道 2x 的存在**，但渲染出来是锐利的——因为浏览器帮你做了一切。

### Ebitengine 怎么处理的？

Ebitengine 没有这个自动机制。`Layout()` 返回什么分辨率，内部画布就是什么分辨率：

```
Layout() 返回 1200×540
Ebitengine 创建 1200×540 的画布
所有绘制在 1200×540 上进行
窗口实际是 2400×1080 物理像素
Ebitengine 把 1200×540 的画布拉伸到 2400×1080 显示
```

**拉伸 = 模糊**。就像把一张小图片放大两倍，边缘会变糊。文字尤其明显，因为文字的笔画很细，放大后锯齿/模糊最容易看出来。

## 为什么我的尝试引发了一连串问题

### 第一步：让 Ebitengine 用原生分辨率渲染

我加了 `LayoutF()` 方法，告诉 Ebitengine："画布用 2400×1080"。

```go
func (g *Game) LayoutF(_, _ float64) (float64, float64) {
    scale := 2.0 // Retina
    return 1200 * scale, 540 * scale // → 2400×1080
}
```

现在画布是 2400×1080，不需要拉伸了，**文字变清晰了**。

### 第二步：但是所有坐标都错了

问题来了。我们的代码写的是：

```go
draw.FilledCircle(screen, 600, 270, 10, red) // 屏幕正中心画个圆
```

在 1200×540 的画布上，(600, 270) 确实是正中心。
但在 2400×1080 的画布上，(600, 270) 变成了**左上角四分之一处**。

正中心应该是 (1200, 540)，也就是 600×2, 270×2。

**所以：画布变大了，但代码里的坐标还是按小画布写的，所有东西都偏到左上角了。**

### 第三步：给每个绘制函数加缩放

为了解决坐标偏移，我在 `draw.*` 包里加了自动缩放：

```go
func FilledCircle(screen, cx, cy, r, clr) {
    // 你传 600, 270（逻辑坐标）
    // 内部乘以 2.0 变成 1200, 540（物理坐标）
    vector.DrawFilledCircle(screen, cx*2, cy*2, r*2, clr, true)
}
```

字体渲染也类似：你传 16px 字号，内部用 32px 光栅化。

### 第四步：鼠标坐标也错了

`ebiten.CursorPosition()` 返回的是物理像素坐标（画布坐标）。画布是 2400×1080 时，点击屏幕正中心返回 (1200, 540)。

但我们的 hit test 代码用的是逻辑坐标：

```go
// "开始游戏"按钮在逻辑坐标 (490, 225) 到 (710, 267)
if mx >= 490 && mx <= 710 && my >= 225 && my <= 267 { ... }
```

鼠标返回 (1200, 540)，不在这个范围内 → **点击无反应**。

修复方法：鼠标坐标除以 2：`mx/2, my/2`。但这个很容易忘记。

### 第五步：精灵（图片）绘制也错了

`screen.DrawImage(img, opts)` 的 `GeoM.Translate(x, y)` 也需要乘以 2。
每个精灵绘制都要手动处理，任何人写新代码忘了乘 2，图就画偏。

### 问题总结

```
浏览器 Canvas:
  你写坐标 → 浏览器自动 ×2 → 物理像素    （你不用管）

Ebitengine:
  你写坐标 → 直接就是物理像素               （你必须自己 ×2）
```

这就是为什么"文字变清晰"后，鼠标点不了、精灵画偏、写新代码要时刻想着缩放。
**Ebitengine 没有浏览器那层自动适配。**

## 最终方案：自己实现 Canvas 那层自动适配

既然 Ebitengine 不帮我们做，那我们自己在 `draw` 包里做，覆盖所有场景：

| Canvas 自动处理的 | 我们的等价实现 |
|-------------------|---------------|
| 形状坐标 ×Scale | `draw.FilledCircle`, `draw.Line` 等（内部自动 ×Scale） |
| 文字坐标和字号 ×Scale | `FontManager.DrawText` 等（内部自动 ×Scale） |
| 图片绘制坐标 ×Scale | `draw.Sprite`, `draw.SpriteScaled`, `draw.SpriteRotated` |
| 鼠标事件坐标 ÷Scale | `draw.CursorPos()`, `draw.TouchPos()` |

**使用规则（写任何渲染代码只需遵守）：**

1. 画形状 → 用 `draw.*`，不用 `vector.*`
2. 画精灵 → 用 `draw.Sprite*`，不手写 `GeoM`
3. 读鼠标 → 用 `draw.CursorPos()`，不用 `ebiten.CursorPosition()`
4. 坐标全部用逻辑值（1200×540 空间），**不用想缩放**

这样就和浏览器 Canvas 一样了——调用方完全不需要知道设备像素比的存在。
