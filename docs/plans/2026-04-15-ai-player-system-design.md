# AI 玩家系统设计

> 2026-04-15 | 状态: 设计中

## 1. 概述

### 目标

为塔防游戏添加一个**AI玩家系统**——一个真正的"队友"，和人类玩家平起平坐，拥有自己的区域、经济、决策权和"人格"。

### 核心体验

> "一个人玩太无聊了。我想看到队友在旁边忙活，看到它在思考、纠结、偶尔犯蠢，然后我们一起赢。"

**不是**：

- 不是萌妹系统（萌妹保持独立，AI 玩家是另一套系统）
- 不是自动战斗（AI 有可见的"思考→决策→行动"过程）
- 不是完美 AI（刻意保留不完美，像真人队友）

### 关键词

| 概念 | 定义 |
|------|------|
| AI 玩家 | 一个独立的游戏参与者，管理自己的区域和经济 |
| 精灵 | AI 玩家在地图上的可见形象，会移动、巡视、操作 |
| 思维气泡 | 精灵头顶的对话气泡，展示 AI 的决策思考过程 |
| Ping | 玩家点击 AI 区域的格子给 AI 发建议信号 |
| 合作地图 | 专为双人设计的地图，双路径分区汇合 |

## 3. AI 决策引擎

### 3.1 决策循环

AI 不是每帧决策，而是模拟"人类节奏"的定时评估：

```
每 2-4 秒（随机间隔，拟人化）:
  1. 感知（Perceive）
     - 扫描自己区域的威胁
     - 评估每条路径的敌人密度和强度
     - 统计自己的经济状态
     - 检查待处理事项（能力选择、道具等）

  2. 规划（Plan）
     - 生成候选行动列表（造塔/升级/选能力/用道具/什么都不做）
     - 按权重评分排序
     - 选择最高分行动（概率性，非确定性）

  3. 表达（Express）
     - 根据行动生成思维气泡文案
     - 精灵移动到目标位置

  4. 执行（Execute）
     - 延迟 0.5-2 秒后执行（模拟思考时间）
     - 播放操作动画
```

### 3.2 决策类型与评估

```go
// 每种决策类型有独立的评估函数，返回 0-100 的优先级分数
type Decision struct {
    Type     DecisionType  // Build / Upgrade / ChooseAbility / UseItem / Idle
    Score    float64       // 0-100 优先级
    Target   GridPos       // 目标位置
    Detail   interface{}   // 类型特定参数
}
```

**造塔评分**（Build）:

| 因子 | 权重 | 说明 |
|------|------|------|
| 路径覆盖 | 30% | 该位置能覆盖多少路径格子 |
| 威胁匹配 | 25% | 当前缺什么类型的塔（DPS/CC/AOE） |
| 经济状态 | 20% | 金币充裕度（买了还剩多少） |
| 个性偏好 | 15% | personality 参数影响 |
| 随机噪声 | 10% | 拟人化不确定性 |

**升级评分**（Upgrade Strength）:

| 因子 | 权重 | 说明 |
|------|------|------|
| 塔的 DPS 贡献 | 40% | 高 DPS 塔优先升级 |
| 性价比 | 30% | 升级收益 / 花费 |
| 位置关键度 | 20% | 覆盖关键路径的塔优先 |
| 噪声 | 10% | 偶尔升级"错误"的塔 |

**能力选择**（Choose Ability）:

| 因子 | 权重 | 说明 |
|------|------|------|
| 能力强度 | 35% | 当前 meta 下的能力强度评分 |
| 塔的定位 | 30% | DPS 塔优先选伤害能力，控制塔选 CC |
| 已有能力互补 | 25% | 避免重复类型，优先填空 |
| 噪声 | 10% | 偶尔选"非最优"的有趣能力 |

### 3.3 个性参数

每个 AI 玩家有一组个性参数，影响决策偏好：

```go
type Personality struct {
    Aggression  float64 // 0-1: 0=防守型（多CC）, 1=进攻型（多DPS）
    Economy     float64 // 0-1: 0=激进花钱, 1=攒钱型
    Risk        float64 // 0-1: 0=保守（留钱应急）, 1=冒险（全投入）
    Reaction    float64 // 0-1: 0=慢反应（3-4s）, 1=快反应（1-2s）
    Compliance  float64 // 0-1: 0=完全无视 ping, 1=总是听建议
}
```

AI 精灵创建时随机 roll 个性参数（正态分布，均值 0.5），每局不同。通过气泡和行为让玩家逐渐感知 AI 的"性格"。

### 3.4 "拟人"细节

让 AI 像真人而非机器的关键设计：

| 行为 | 实现方式 |
|------|---------|
| 思考延迟 | 决策后 0.5-2s 才执行，越难的决策延迟越长 |
| 巡视行为 | 空闲时精灵在区域内随机巡视，而非静止不动 |
| 犹豫/反悔 | 10% 概率：走到位置后改变主意，气泡显示"算了..." |
| 次优选择 | 15% 概率选择第二优方案（真人也不总是最优） |
| 情绪反应 | 漏怪时：精灵跑向漏怪方向 + 气泡"啊！" |
| 经济焦虑 | 穷的时候反复走来走去 + "缺钱了..." |
| 成就感 | 连续击杀时加速移动 + "打得不错！" |
| 队友关注 | 偶尔精灵面向玩家区域 + "那边还好吗？" |

## 4. 精灵表现层

### 4.1 精灵状态机

```
                ┌────────────┐
                │   Idle     │ ← 默认：区域内缓慢巡视
                └─────┬──────┘
                      │ 新决策
                ┌─────▼──────┐
                │  Moving    │ ← 移动到目标位置
                └─────┬──────┘
                      │ 到达
                ┌─────▼──────┐
                │ Thinking   │ ← 头顶冒出思维气泡（0.5-2s）
                └─────┬──────┘
                      │ 决定
                ┌─────▼──────┐
                │ Executing  │ ← 执行操作（造塔/升级动画）
                └─────┬──────┘
                      │ 完成
                ┌─────▼──────┐
                │ Reacting   │ ← 对结果的情绪反应（0.3-0.8s）
                └─────┬──────┘
                      │
                      └──────► Idle
```

### 4.2 精灵视觉

- **大小**: 32x32 逻辑像素（与敌人精灵尺寸接近）
- **外观**: 可辨识的"AI 队友"形象（半透明能量体 / 小机器人 / 光球 — 待定美术风格）
- **动画**: idle 悬浮 bob（正弦波，同萌妹）+ 移动方向面朝
- **区域指示**: 精灵下方有淡色区域边界线，标识 AI 的地盘
- **操作预览**: 准备造塔时，目标格子显示半透明虚影（0.5-1s 后实体化）

### 4.3 思维气泡系统

气泡类型：

| 类型 | 样式 | 触发 | 持续 |
|------|------|------|------|
| 思考 | `💭` 云状气泡 | 决策评估中 | 1-3s |
| 行动 | `💬` 普通气泡 | 执行操作时 | 1-2s |
| 情绪 | `❗`/`❓` 强调气泡 | 漏怪/意外事件 | 0.5-1s |
| 回应 | `💬` 带箭头 | 回应玩家 ping | 1-2s |

## 5. 合作地图设计

### 5.1 地图规格

| 参数 | 值 | 说明 |
|------|-----|------|
| 尺寸 | 40x15 | 40 列 × 15 行 |
| CellSize | 45px | 总像素 1800x675 |
| 可建造格 | 约 60 格 | 每个区域约 30 格 |
| 路径 | 双路径 | 分叉后各自穿过一个区域，最后汇合 |
| 波数 | 15-20 | 中等长度 |

### 5.2 地图结构

```
    Col 0                Col 20               Col 39
     ┌──────────────────┬──────────────────────┐
     │                  │                      │  Row 0
     │   ┌─ 入口A ──────┤                      │
     │   │              │                      │
     │   │  [玩家区域]   │   汇合路径 ──► 终点   │
     │   │  30 格可建造  │                      │  Row 7
     │   │              │                      │
     │   │              │                      │
     │   └─ 入口B ──────┤                      │
     │                  │                      │
     │   ┌─ 入口C ──────┤                      │
     │   │              │                      │
     │   │  [AI 区域]   │                      │
     │   │  30 格可建造  │                      │  Row 14
     │   │              │                      │
     │   └─ 入口D ──────┤                      │
     │                  │                      │
     └──────────────────┴──────────────────────┘
```

实际路径设计：

- **分叉型**: 敌人从左侧中央入口进入，路径立刻分叉，上路穿过玩家区域，下路穿过 AI 区域，最后在右侧汇合进入 Boss 区/终点
- **权重**: 各 50%（各路径承担一半敌人）
- **汇合区**: 右侧有少量共享可建造格，双方都能在此造塔（争夺/协作点）

### 5.3 区域所有权

```go
type ZoneOwner int

const (
    ZoneNeutral ZoneOwner = iota // 汇合区，双方可用
    ZoneHuman                    // 玩家专属区域
    ZoneAI                       // AI 专属区域
)
```

- 地图 JSON 新增 `zones` 字段，定义每个可建造格的归属
- 玩家只能在 ZoneHuman + ZoneNeutral 造塔
- AI 只能在 ZoneAI + ZoneNeutral 造塔
- 汇合区（Neutral）格子数有限（约 6 格），形成"谁先占谁的"竞争点

### 5.4 经济独立

| 参数 | 玩家 | AI |
|------|------|-----|
| 初始金币 | 正常值 | 正常值 × 1.0（同等） |
| 击杀收入 | 自己区域击杀的归自己 | 同 |
| 汇合区击杀 | 谁的塔打最后一击归谁 | 同 |
| 波次奖励 | 各拿 50% | 同 |
| 生命值 | **共享** | 任何区域漏怪都扣共享生命 |

共享生命是核心张力点——你的失误会坑队友，队友的失误也影响你。

## 6. 玩家与 AI 的交互

### 6.1 Ping 系统

玩家点击 AI 区域的格子，发出一个 Ping 信号：

```
操作流程:
1. 玩家点击 AI 区域的某个格子
2. 格子闪烁高亮 + 发出 ping 音效
3. AI 精灵转头看向 ping 位置
4. AI 评估 ping 建议（1-2s 延迟）
5. AI 回应：
   - 同意 (Compliance 高 / ping 位置确实好): 精灵走过去造塔
   - 拒绝 (Compliance 低 / 不认同): 气泡回应原因
   - 折中: "等一下，我先处理完这个"
```

Ping 冷却: 10 秒（防止刷屏干扰 AI）

### 6.2 AI 对玩家的关注

AI 不只管自己的事，偶尔也会"看"玩家区域：

- 玩家区域漏怪 → AI 气泡："那边漏了！"
- 玩家长时间不操作 → "你还在吗？"
- 玩家造了好塔 → "那个位置不错啊"
- 玩家卖塔 → "哦？要调整布局？"

### 6.3 后续扩展（Phase 4+）

- **互送道具**: 拖动道具到 AI 区域边界 → 投送给 AI
- **战灵借调**: 临时把战灵派到队友区域帮忙
- **联合技能**: 双方同时 ping 同一区域 → 触发合作 buff

## 7. LLM 集成（Phase 3）

### 7.1 职责划分

| 层级 | 实现 | 职责 |
|------|------|------|
| 策略决策 | 本地规则引擎 | 造塔/升级/选能力（快、免费、离线可用） |
| 语言表达 | LLM（Haiku 级） | 将决策+局势转化为自然语言弹幕 |

### 7.2 调用频率与 Prompt

- 触发时机: 每 30 秒一次 / AI 做重要决策时 / 玩家 ping 时
- 预期延迟: 1-3 秒（Haiku 模型）
- 降级方案: LLM 不可用时 fallback 到本地模板文案

Prompt 结构:

```
你是塔防游戏中的 AI 玩家"小助手"。你正在和一个人类队友一起守关。

当前局势:
- 第 {wave}/{totalWaves} 波
- 你的金币: {aiGold}, 队友金币: {humanGold}
- 共享生命: {lives}/{maxLives}
- 你的区域: {aiTowerCount} 座塔, 威胁等级 {threatLevel}
- 队友区域: {humanTowerCount} 座塔
- 你刚刚: {lastAction}
- 队友刚刚: {humanLastAction}

用一句话（<20字）表达你当前的想法或对局势的反应。
要求：口语化、有个性、偶尔吐槽、偶尔夸队友。
```

### 7.3 成本估算

| 参数 | 值 |
|------|-----|
| 调用频率 | ~2次/分钟 |
| 每次 token | ~200 input + ~30 output |
| 每局时长 | ~15 分钟 |
| 每局调用 | ~30 次 |
| 每局成本 | ~30 × 230 tokens × $0.25/MTok ≈ **$0.002/局** |

极低成本，完全可接受。

## 9. 分期路线图

### Phase 1: AI 骨架（最小可玩原型）

**目标**: 在现有大地图上跑通"AI 自动造塔"的基本循环

- [ ] `aiplayer.go` 核心结构体 + Tick 入口
- [ ] 简单 DecisionEngine: 只做"造塔"决策（随机选可建造格 + 简单评分）
- [ ] AI 精灵: 地图上一个可见的精灵，移动到目标位置
- [ ] 思维气泡: 最简版本（固定模板文案）
- [ ] 区域划分: 现有大地图按列号硬编码划分（左半=玩家，右半=AI）
- [ ] 独立经济: AI 有自己的金币余额
- [ ] Stage 集成: `updatePlaying()` 中调用 `aiPlayer.Tick()`

**验收标准**: 开一局能看到 AI 精灵在右半区域自己造塔、冒气泡

### Phase 2: 决策深度

**目标**: AI 做出有质量的决策，行为可观察可理解

- [ ] 完整评估函数: 威胁评估、位置评分、类型需求分析
- [ ] 升级决策: 何时升级哪座塔
- [ ] 能力选择: 能力 3 选 1 的评估逻辑
- [ ] 道具使用: 自动使用道具到最合适的塔
- [ ] 个性系统: 随机个性影响决策偏好
- [ ] 拟人行为: 延迟、犹豫、次优选择、情绪反应
- [ ] 战灵选择: AI 自动选择战灵

**验收标准**: AI 能通关 Normal 难度，行为看起来"像个新手玩家"

### Phase 3: LLM 弹幕 + 交互

**目标**: AI 说人话，玩家能和 AI 互动

- [ ] LLM Connector: Haiku API 集成
- [ ] 局势摘要: 结构化数据 → prompt
- [ ] 弹幕系统: LLM 输出 → 思维气泡
- [ ] Ping 系统: 玩家点击 AI 区域给建议
- [ ] Ping 响应: AI 评估并回应（同意/拒绝/折中）
- [ ] LLM fallback: API 不可用时退回本地模板

**验收标准**: AI 在关键时刻说出有语境的自然语言，对 ping 有合理回应

### Phase 4: 合作地图

**目标**: 专为双人设计的地图，完整的合作体验

- [ ] 合作地图编辑/设计（至少 2 张）
- [ ] 地图 zones 字段加载和渲染
- [ ] 区域所有权校验（玩家不能在 AI 区域造塔）
- [ ] 汇合区共享格子机制
- [ ] 经济独立 + 击杀归属
- [ ] 相机系统适配（大地图 1800px 宽）

### Phase 5: 深度协作

**目标**: 增加多人专属的交互决策点

- [ ] 互送道具
- [ ] 战灵借调
- [ ] AI 对玩家行为的评论系统（LLM 驱动）
- [ ] 难度自适应: AI 强度根据玩家水平动态调整
- [ ] 多 AI 支持: 3-4 人合作地图（2-3 个 AI）

## 10. 风险与注意事项

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| AI 太强玩家没事做 | 体验差 | 限制 AI 决策速度 + 加入次优选择 |
| AI 太弱总是输 | 体验差 | 难度自适应 + 个性"强度"参数可调 |
| LLM 延迟影响体验 | 气泡延迟 | 异步调用 + 本地 fallback |
| AI 决策逻辑复杂度 | 开发量大 | Phase 1 先做最简版本验证体验 |
| 合作地图设计难 | 需要平衡测试 | 复用现有 spawner 逻辑，经济参数可调 |
| TowerPool Owner 改动大 | 影响现有逻辑 | Tower 加 Owner 字段，默认 Human，最小侵入 |

### 性能预估

| 开销 | 预估 | 说明 |
|------|------|------|
| AI Tick | <0.1ms/帧 | 2-4s 评估一次，其余帧只做精灵移动 |
| 精灵渲染 | 1 sprite + 1 text | 可忽略 |
| LLM 调用 | 每 30s 一次，异步 | 不阻塞游戏循环 |
| 额外塔/敌人 | 地图大了 1.5x | 在现有池容量内，无需扩容 |
